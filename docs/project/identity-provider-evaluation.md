# Teluni Identity Provider Evaluation

[Selected policies](identity-and-access.md) · [PH-11](human-actions.md#ph-11) · [ADR-0024 decision](../adr/0024-propose-keycloak-and-server-managed-human-sessions.md)

## Evaluation scope and result

On **2026-10-18**, the owner selected self-hosting and **Keycloak**, then explicitly approved all pending Teluni ADRs, including ADR-0024/ADR-0025. Host feasibility and actual integration qualification remain delivery prerequisites. No recurring identity/email procurement budget is available. This is a documentation/source review, not a deployed-provider experiment, security assessment or proof of operational capacity. Keycloak **26.8.1**, release published on 2026-10-13, was inspected at source commit `24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b` for the assessment below. This pins review evidence only; no deployment image/digest has been selected or installed. Reassess the deployment version and security status before implementation; mutable `latest` documentation does not pin a production dependency.

The existing [verifier](../../apps/api/src/authentication.ts) and accepted [ADR-0012](../adr/0012-verify-jwt-access-tokens-at-the-first-api-boundary.md) are the executable/governing boundary. Do not weaken it because a candidate emits different defaults. The source/documentation review and explicit owner approval satisfy PH-11's architectural decision scope. They do not qualify a running integration. Required policies and measured bounds remain in the [identity policy](identity-and-access.md), not vendor defaults.

The `orion_*` claim names are an inherited application contract, not a demand to rebrand them or use Keycloak subjects as application IDs. Mapping a UUID-looking user-editable attribute is insufficient. Pin principal creation, authoritative ownership, `(issuer, subject)` association, uniqueness and migration semantics during design. Do not add machine-client grants to a human client and assume a hardcoded actor mapper distinguishes them. Provider roles may inform trusted mapping but cannot replace current application memberships/resource permissions.

## Pinned-source assessment

Evidence was read from the official [26.8.1 release](https://github.com/keycloak/keycloak/releases/tag/26.8.1) and the immutable source commit above. Nine Java source files were downloaded outside the repository for inspection; no downloaded code was executed, provider started or token issued. This is a supported architectural compatibility assessment, not an interoperability test.

| Existing API requirement                | Pinned-source evidence / accepted integration responsibility                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Exact `typ=at+jwt`                      | [DefaultTokenManager](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/jose/jws/DefaultTokenManager.java) selects the RFC 9068 access-token header when the client option is enabled; [OIDCConfigAttributes](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/server-spi-private/src/main/java/org/keycloak/protocol/oidc/OIDCConfigAttributes.java) defines `access.token.header.type.rfc9068`. Configure it explicitly; do not change the existing verifier's accepted type                                                                                                                                                                                                                                                                                    |
| Signed tokens and exact issuer/audience | The signing path in DefaultTokenManager uses the configured signature provider. [TokenManager](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/protocol/oidc/TokenManager.java) sets issuer; [SubMapper](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/protocol/oidc/mappers/SubMapper.java) supplies the persistent user subject; [AudienceProtocolMapper](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/protocol/oidc/mappers/AudienceProtocolMapper.java) adds the configured audience. The integration must select RS256 or ES256 and the exact trusted API issuer/audience/JWKS, then test actual signatures/key rotation and denial cases |
| `sub`, `iat`, `exp`, string `scope`     | TokenManager initializes access tokens from the authenticated user/session and sets the scope string; [AccessToken](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/core/src/main/java/org/keycloak/representations/AccessToken.java) and [JsonWebToken](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/core/src/main/java/org/keycloak/representations/JsonWebToken.java) define their representation/time lifecycle. Actual emitted types, clock bounds and expiry remain verifier integration tests                                                                                                                                                                                                                                                                                            |
| Application principal UUID              | [UserAttributeMapper](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/protocol/oidc/mappers/UserAttributeMapper.java) maps a configured user attribute into a configured token claim. Trusted provisioning must generate an application UUID, keep a unique stable `(issuer, subject)` association and map a non-user-editable attribute to `orion_principal_id`. User profile edits, signup, Google imports and tenant administrators cannot create/replace that attribute; fail closed until the trusted mapping exists                                                                                                                                                                                                                                                                         |
| Trusted human assertion                 | [HardcodedClaim](https://github.com/keycloak/keycloak/blob/24ed1dadf3f246a555adb6d3d4a99e9b3003fb3b/services/src/main/java/org/keycloak/protocol/oidc/mappers/HardcodedClaim.java) can supply `orion_actor_type=human` only in a restricted human-login client/flow. Disable service-account, password/direct-grant and unreviewed exchange/impersonation paths on that client; a constant mapper alone does not prove a human. Test that machine credentials cannot produce an accepted human token                                                                                                                                                                                                                                                                                                                                                                     |
| Session/assurance freshness             | The current verifier deliberately returns only principal/scopes. The reviewed OIDC boundary must bind verified login assertions and current server session/assurance state to that principal and the legitimate access token. An ID token may establish login context at its intended OIDC boundary but never substitutes for the API access token. Enforce the 30-second session/membership revocation goal using application state, not unimplemented claims or provider logout alone                                                                                                                                                                                                                                                                                                                                                                                  |

The review found a viable standards-based mapping path without changing ADR-0012. It does not assert that a default Keycloak client/token already meets the contract. Immutable principal provisioning, protected profile attributes, human-only flow restrictions and trusted session/assurance binding are mandatory implementation design/control requirements under PJ-07/PJ-24, not controls that were deployed in this task. Deployment version/image selection remains PH-15/PJ-24.

## Alternatives and tradeoffs

| Direction                                                     | Assessment for the current decision                                                                                                                                                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Self-hosted Keycloak                                          | Owner-approved provider; operational control with responsibility for resources, upgrades, mail and recovery. Documentation indicates relevant primitives; integration remains unqualified                                       |
| Managed established OIDC provider                             | Could reduce some hosting responsibilities, but recurring cost, limits, claim compatibility and migration would need a new evaluation. No vendor price/free-tier comparison or rejection on unsupported cost claims is asserted |
| Another established self-hosted provider                      | Remains a fallback if Keycloak cannot meet required compatibility/operations. No comparative benchmark has been performed; a provider change after acceptance requires a new reviewed decision                                  |
| API-owned passwords, home-grown issuer or weakened JWT checks | Not an acceptable shortcut under inherited authentication policy/ADR-0012                                                                                                                                                       |

The owner also selected server-managed browser sessions over a browser-token SPA direction. This keeps provider credentials off browser JavaScript but adds session persistence, CSRF defenses and lifecycle/revocation work. It can compose into the modular backend; it neither mandates a new service nor changes the client-first web architecture to server rendering.
