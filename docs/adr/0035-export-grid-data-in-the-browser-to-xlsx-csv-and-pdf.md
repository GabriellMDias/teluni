# ADR-0035: Export Grid Data in the Browser to XLSX, CSV and PDF

**Status:** accepted
**Date:** 2026-10-27

**Acceptance scope:** On 2026-10-27 the owner asked for exports of the data the shared `DataSet` shows, at least to Excel and PDF, and left further formats and the technology to the agent. The agent accepted this decision under that request and the delegation recorded with [PH-25](../project/human-actions.md#ph-25); merging the pull request that adds it is the repository review. It covers exports of rows the browser already shows. It adds no export endpoint or server-side report.

## Context

[ADR-0034](0034-build-data-grids-on-tanstack-table-and-tanstack-virtual.md) gives the web panel a grid that sorts and filters the rows it holds. People need to take that view elsewhere: analyze it in a spreadsheet, load it into another system, or print and share it. The rows are already authorized for the person and present in the browser, and the grid can hold tens of thousands of them. Teluni's audience works mostly in Portuguese spreadsheets, which expect `;` separators and decimal commas in CSV. Export code must not slow the first page load.

## Decision

- Grids offer three formats, opt-in per screen through `exportName`:
  - **Excel (.xlsx)** through `write-excel-file`, keeping numbers numeric, the header bold and frozen, and the column widths shown;
  - **CSV** generated by the product: UTF-8 with a byte order mark, CRLF lines, the locale's separator and decimal mark (`;` and `,` in Portuguese), and text that a spreadsheet would run as a formula prefixed with `'`;
  - **PDF** through `jsPDF` with `jspdf-autotable`: A4, landscape for wide grids, a title, the generation time and record count, and page numbers.
- An export contains the rows the grid shows, in their order and with its filters, and the columns that have a value. It runs entirely in the browser.
- The libraries are pinned exactly and loaded with dynamic `import()` only when someone exports.

## Rationale

- XLSX keeps types and opens directly in Excel, LibreOffice and Google Sheets; CSV is what other systems import; PDF is what people print, attach and sign off. A JSON export would serve developers rather than the panel's users and is left out.
- `write-excel-file` is MIT-licensed, maintained, browser-first and depends only on `fflate`. The SheetJS package on the public registry stopped at 0.18.5 in 2022 with known advisories, and ExcelJS has not been released since 2023 and pulls Node-oriented dependencies.
- `jsPDF` with `jspdf-autotable` is the established MIT pair for tables in the browser, paginates repeated headers and handles Portuguese accents with its built-in Helvetica (WinAnsi encoding).
- Generating CSV needs no library; doing it in the product keeps the locale and formula-injection rules explicit and tested.
- In a development build, 10,000 rows exported in about 0.1 s to CSV, 0.6 s to XLSX and 3 s to a 7 MB PDF.

## Alternatives Considered

### Print the page to PDF

The browser's print dialog would need no library, but virtualization renders only the rows in view, and saving a PDF would depend on the person choosing a printer destination.

### Server-side exports

An API export could cover more rows than the browser holds, but it needs endpoints, authorization and limits for each list. It remains possible for lists that add server-side sorting and filtering.

## Consequences

### Positive

- Every screen with a grid can offer the same three exports by passing one prop; the first page load does not include the export libraries.

### Negative

- Three runtime dependencies to keep current. jsPDF installs optional packages (html2canvas, DOMPurify, canvg, core-js) that the build emits as unused lazy chunks; core-js's install script stays disabled.
- The PDF uses a standard font, so characters outside WinAnsi, such as emoji, do not print. Very large PDFs take seconds and many pages.
- `fflate` compresses XLSX in a worker created from a `blob:` URL; a future Content Security Policy must allow `worker-src blob:`.

### Operational or Migration Impact

- Exports are files the person saves on their device; the product does not log or store them. A screen that must not let records leave the panel simply omits `exportName`.
