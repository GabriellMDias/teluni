# Media Module

This module owns the company media library: images and videos, their processing into playback renditions, storage and lifecycle under [ADR-0028](../../../../../docs/adr/0028-propose-local-content-addressed-media-storage-and-isolated-ffmpeg-processing.md) and the [media library design](../../../../../docs/project/media-library-design.md). Read both before changing behavior.

- Uploaded bytes are untrusted. Admission checks the declared type and size; the processor checks the file signature, forces the matching demuxer and reads files only through FFmpeg/ffprobe child processes started by `ffmpeg.ts` (no shell, PATH-only environment, `-protocol_whitelist file`, timeouts, process-group kill, `prlimit` where present). Never pass user text (names, tags) to a tool, and never log tool output, paths, hashes or file names.
- Objects are content-addressed per company under `<root>/objects/<companyId>/` and only `storage.ts` builds paths. Publish an object (insert its row and rename the work file) only inside a transaction holding `lockObject` for that hash. Release one by checking references and deleting the row under that lock, and unlink the file only after the transaction commits, through `removeFiles`/`removeUnrecorded`, which take the lock again and keep the file if the row exists. A purge and an upload of the same bytes then never lose a file, and a rollback never leaves a row without its file; an orphan file is swept.
- Human operations resolve access through the organizations `CompanyAccessPort` and take its `lockForWrite` before locking asset rows; then the asset row, then object locks. A hidden item answers `RESOURCE_NOT_FOUND`. `PURGED` rows stay for audit and are never visible.
- Processing claims rows with a lease and an attempt fencing token; every finishing write checks both, so a superseded attempt changes nothing. Rejections are permanent and release the original; failures retry with backoff up to `mediaPolicy.maxAttempts`.
- Modules that reference media register a guard through `public.ts` (`registerReferenceGuard`) and select media only through `requireSelectable`. Deletion and purge refuse while any guard reports a reference. Each human change writes its `media_audit_events` row in the same transaction; details hold IDs, sizes and settings only.
