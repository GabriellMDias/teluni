# Catalogs Module

This module owns typed catalogs, their fields, items (records), base prices, branch prices and promotions under the [catalog and composition design](../../../../../docs/project/catalog-composition-design.md) and [ADR-0032](../../../../../docs/adr/0032-represent-money-as-integer-minor-units-with-a-currency-per-field.md). Read both before changing behavior.

- `domain.ts` is pure: field settings, schema planning, value validation, money amounts, promotion overlap and the effective price. Money is an integer count of the field currency's minor units, never a float; numbers are canonical decimal strings. Keep the currency table aligned with `Intl.NumberFormat` (its test fails otherwise) and with the player when protocol 2 lands.
- A field's type, currency, decimals and reference target never change; the runtime grants refuse updates to those columns. Schema saves are whole lists with the catalog version; checks that depend on stored items run in the save's transaction and report counts as envelope issues, never values.
- Human operations resolve access through the organizations `CompanyAccessPort` and take its `lockForWrite` before any catalog row. Then lock the catalog row (`update` for schema, catalog and order changes and item creation; `share` for item and price writes; `delete` for deletion; `key` for a reference target), then item rows, then media and referenced items. A hidden catalog answers `RESOURCE_NOT_FOUND`.
- Item edits need `catalogs.edit` on the catalog's scope and never touch money fields; prices need `prices.edit` on the scope they affect (the catalog's for base prices and scope-wide promotions, the branch's for branch prices and branch promotions), which always needs strong authentication.
- Every price write (base price, branch price, promotion creation or deletion) ends with `#priceChanged` in its transaction: it increments the catalog's `catalog_price_sequences` row, which numbers changes in commit order, and runs the registered price change listeners with the branch it reaches (null for the whole scope). A listener's refusal answers `PRICE_TARGET_FORBIDDEN` and rolls the change back, so a price never changes without being queued for the programs that show it ([automatic price publication](../../../../../docs/project/catalog-composition-design.md#automatic-price-publication)).
- Item values mirror their media and references into `catalog_record_media` and `catalog_record_references` in the same transaction. The module registers the `catalog-record` media reference guard, which must stay read-only. New media go through the media port's `requireSelectable` and must be images of the company or the catalog's branch.
- Other modules use catalogs only through [`public.ts`](public.ts): bindable fields, visibility, view data for previews and protocol 2 publications (read in one repeatable-read snapshot with its price sequence, never under the caller's locks), price sequences, price change listeners and usage guards. A registered usage guard runs inside catalog deletion and schema saves (after the catalog's `update` or `delete` lock) and must stay read-only; a bound catalog answers `CATALOG_IN_USE` on deletion, and a bound field cannot be removed or archived (`FIELD_BOUND` with the count of layouts).
- Every change writes its `catalog_audit_events` row in the same transaction, with the branches it concerns; details hold names, field IDs, counts, versions and, for prices, old and new amounts with their currency, never item values.
