# Programming Module

This module owns playlists, programming groups, the draft programs of groups and screens, schedule rules, screen assignments and timelines under the [programming design](../../../../../docs/project/programming-design.md) and [ADR-0029](../../../../../docs/adr/0029-propose-temporal-based-schedule-evaluation-with-shared-fixtures.md). Read both before changing behavior.

- `schedule.ts` is pure: it never reads a clock or the process time zone and takes IANA zone names explicitly. Keep conflict validation in local wall-clock minutes and zone resolution (gaps to the transition instant, repeated hours earlier for starts and later for ends, then the handoff clip) in the evaluator. Every behavior change updates the canonical [fixtures](../../../test/programming/schedule-fixtures.json), which the player (PJ-12) also runs; never change an expected result to make a test pass.
- Human operations resolve access through the organizations `CompanyAccessPort` and take its `lockForWrite` before any programming row. Then lock in this order: screen rows (through the devices port's `describe` with a transaction), settings, groups, playlists. A resource the caller can see only partly, such as a group spanning a branch outside their reach, answers `RESOURCE_NOT_FOUND`.
- A rule or default may use a playlist only when every branch its program can reach is inside the playlist's scope; new media in a playlist must be selected through the media port's `requireSelectable` and fit the playlist's scope.
- The module registers the `playlist-draft` media reference guard, the branch archive guard for explicit group spans and the devices move hook. They run inside the other module's transaction and must stay read-only, except the move hook, which updates the screen's settings in the move's transaction.
- Assignments never edit programs. Until publication (PJ-11) exists every assignment needs `confirmUnpublished`; PJ-11 replaces that check with the published state.
- Every change writes its `programming_audit_events` row in the same transaction, with the branches it concerns; details hold names, counts, versions and IDs only.
